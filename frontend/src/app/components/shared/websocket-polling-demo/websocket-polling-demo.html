¿Qué es WebSocket?

Protocolo de comunicación bidireccional en tiempo real sobre TCP. Mantiene una conexión persistente entre cliente y servidor.

Ventajas:

  • Latencia mínima (<100ms)
  • El servidor puede PUSH datos al cliente
  • Eficiente para actualizaciones frecuentes
  • Ideal para chat, notificaciones, dashboards en vivo

Casos de uso: Chat, juegos online, trading, monitoreo en tiempo real

@Injectable({{'{'}} providedIn: 'root' {{'}'}})

  connect(url = 'wss://api.miapp.com/notifications') {{'{'}}
    if (!this.socket$ || this.socket$.closed) {{'{'}}
      this.socket$ = webSocket(url);
    {{'}'}}
    return this.socket$;
  {{'}'}}

  listen<T>(): Observable<T> {{'{'}}
    return this.connect().asObservable();
  {{'}'}}

  send(message: any) {{'{'}}
    this.connect().next(message);
  {{'}'}}

  close() {{'{'}}
    this.socket$?.complete();
    this.socket$ = null;
  {{'}'}}
{{'}'}}

⏱️ HTTP Polling - Consultas Periódicas

{{ pollingActive() ? '🟢 Activo' : '🔴 Inactivo' }}

¿Qué es HTTP Polling?

Técnica donde el cliente consulta periódicamente al servidor para obtener actualizaciones. Simula "tiempo real" con HTTP tradicional.

Ventajas:

  • Simple de implementar (HTTP normal)
  • Compatible con cualquier servidor
  • No requiere infraestructura WebSocket
  • Funciona detrás de proxies/firewalls

Desventajas: Mayor latencia, más consumo de red, carga en servidor

// Service
pollNotifications(intervalMs = 30000): Observable<Notification[]> {{'{'}}
  return timer(0, intervalMs).pipe(
    switchMap(() => this.http.get<Notification[]>('/api/notifications')),
    shareReplay(1) // Reutiliza última respuesta
  );
{{'}'}}

// Component
notifications$ = this.service.pollNotifications(30000);

// Template con async pipe
<div *ngIf="notifications$ | async as notifications">
  <div *ngFor="let notif of notifications">
    {{'{{'}} notif.message {{'}}'}}
  </div>
</div>

// Alternativamente con signals
ngOnInit() {{'{'}}
  timer(0, 30000).pipe(
    switchMap(() => this.http.get<Notification[]>('/api/notifications')),
    takeUntil(this.destroy$)
  ).subscribe(notifications => {{'{'}}
    this.notifications.set(notifications);
  {{'}'}});
{{'}'}}

📊 Comparativa: WebSocket vs Polling

Criterio WebSocket HTTP Polling
Latencia <100ms Depende del intervalo (3-30s típico)
Dirección Bidireccional (servidor puede push) Cliente pull (solo cliente pregunta)
Consumo red Bajo (conexión persistente) Alto (HTTP headers en cada request)
Complejidad Media (requiere servidor WebSocket) Baja (HTTP normal)
Escalabilidad Requiere más recursos servidor Más simple de escalar
Firewall/Proxy Puede tener problemas Compatible universalmente
Reconexión Requiere lógica de reconexión Automático (cada request)

💡 Recomendaciones

✅ Usa WebSocket para:

  • Chat en tiempo real
  • Dashboards con datos en vivo
  • Juegos online multijugador
  • Trading / finanzas
  • Notificaciones instantáneas
  • Colaboración en tiempo real

✅ Usa HTTP Polling para:

  • Actualizaciones cada 30s+
  • Compatibilidad máxima
  • Servidor sin soporte WebSocket
  • Datos que cambian poco
  • Entornos corporativos restrictivos
  • Prototipado rápido
